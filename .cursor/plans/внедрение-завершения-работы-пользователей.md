# Внедрение подсистемы БСП «Завершение работы пользователей»

Цель: клиенты «Вышибалы» предупреждают о приближении блокировки начала сеансов (из консоли кластера или из формы БСП) и завершают работу при ее наступлении.

Способ: объединение с конфигурацией поставщика (БСП 3.1.12.323 уже на поддержке, правило «Редактируется с сохранением поддержки»), в Конфигураторе, с последующим переносом в EDT-проект.

Точки вызова подсистемы в ядре БСП уже есть (`ПодсистемаСуществует("СтандартныеПодсистемы.ЗавершениеРаботыПользователей")` в `ИнтеграцияПодсистемБСП*`, `СерверныеОповещения*`, `СтандартныеПодсистемыКлиент`), поэтому модули ядра не объединяются.

## 0. Подготовка

1. В EDT закоммитить или отложить текущую работу (назначение баз операторам), чтобы внедрение ушло отдельным коммитом.
2. В EDT обновить конфигурацию ИБ из проекта (без `fullUpdate`). Конфигурация ИБ должна совпадать с проектом, иначе при обратном импорте смешаются чужие расхождения.
3. Закрыть все сеансы этой ИБ из EDT (запуски, отладка). До шага 5 ничего не править в EDT и не запускать из него обновление ИБ: EDT перезапишет конфигурацию ИБ версией проекта.
4. Резервная копия: в Конфигураторе «Администрирование, Выгрузить информационную базу» (`.dt`) и «Конфигурация, Сохранить конфигурацию в файл» (`.cf`).

## 1. Сравнение с конфигурацией поставщика

1. Конфигуратор, «Конфигурация, Открыть конфигурацию».
2. «Конфигурация, Поддержка, Настройка поддержки», кнопка «Сравнить, объединить».
3. В окне сравнения оставить режим «Показывать только отличия».
4. Снять все флажки у корня дерева.
5. «Действия, Отметить по подсистемам» (подсистемы конфигурации поставщика): выбрать только `СтандартныеПодсистемы, ЗавершениеРаботыПользователей`, включая подчиненные.

## 2. Ревизия флажков (главный шаг)

Пройти все отмеченные строки. Оставить флажок только если:

- объект **отсутствует** в основной конфигурации (левая колонка пустая): общие модули `СоединенияИБ*`, обработки и общие формы подсистемы, ее картинки;
- это сама подсистема `СтандартныеПодсистемы.ЗавершениеРаботыПользователей` (узел внутри `СтандартныеПодсистемы, Подсистемы`).

Снять флажок, если объект **есть в обеих** конфигурациях и отличается: это урезанная или доработанная версия БСП, объединение вернет вырезанное или затрет правки. Отдельно проверить, что не отмечены:

- корень конфигурации и его свойства (модули приложения, основные роли, состав подсистем верхнего уровня);
- модули ядра: `ОбщегоНазначения*`, `СтандартныеПодсистемы*`, `ИнтеграцияПодсистемБСП*`, `СерверныеОповещения*`;
- формы `ПанельАдминистрированияБСП`;
- роли (права на новые объекты выдаст `setForNewObjects` у `ПолныеПрава`);
- собственные объекты «Вышибалы» и подсистема `Администрирование`.

Перед выполнением: «Действия, Сохранить настройки объединения в файл» (для повтора и разбора).

## 3. Выполнение

1. «Выполнить».
2. Окно проверки ссылочной целостности (если появится):
   - объект отсутствует в основной и нужен подсистеме (картинка, элемент стиля, общая форма): отметить;
   - объект есть в основной и отличается: не отмечать, разобрать после;
   - объект из невнедренной подсистемы (`РаботаВМоделиСервиса`, `ОбновлениеКонфигурации`, `РезервноеКопированиеИБ` и т.п.): отменить объединение и разобраться, откуда прямая ссылка. Обычно в БСП такие ссылки через `ОбщийМодуль()` и в проверку не попадают.
3. Правило поддержки для новых объектов: «Объект поставщика редактируется с сохранением поддержки», как у остальной БСП.

## 4. Проверка в Конфигураторе

1. «Конфигурация, Проверка конфигурации»: логическая и ссылочная целостность, синтаксический контроль, расширенная проверка для тонкого клиента, веб-клиента, сервера, внешнего соединения.
2. Ошибки «метод не найден» в `СоединенияИБ*` означают, что урезанное ядро не содержит нужного метода. Недостающее брать из конфигурации поставщика точечно (сравнение по объекту), модули ядра не объединять целиком. Если правка ядра неизбежна: маркеры `// <<МОДИФИКАЦИЯ` ... `// >>`.
3. F7, обновить конфигурацию базы данных.
4. Быстрая проверка в 1С:Предприятии (см. раздел 6, пункты 1-2).

## 5. Перенос в EDT

1. В EDT импортировать изменения из информационной базы в проект (контекстное меню ИБ в панели «Информационные базы»; название пункта зависит от версии EDT). Принять входящие изменения.
2. Проверить `git status` / diff. Ожидаемо:
   - новые `src/CommonModules/СоединенияИБ*`, обработки и общие формы подсистемы;
   - `src/Subsystems/СтандартныеПодсистемы/Subsystems/ЗавершениеРаботыПользователей`;
   - `src/Configuration/Configuration.mdo` (регистрация объектов);
   - роли (права на новые объекты);
   - настройки поддержки.

   Неожиданно: изменения в существующих модулях БСП и собственных объектах. Разобрать, при необходимости откатить точечно.
3. `get_project_errors` / `get_problem_summary`.
4. Командный интерфейс: если в урезанной `ПанельАдминистрированияБСП` нет элементов блокировки, добавить команду формы блокировки в `Subsystem.Администрирование`, форму панели не объединять.
5. Коммит отдельным изменением «Внедрение БСП: Завершение работы пользователей».

## 6. Проверка поведения

1. В консоли кластера блокировка тестовой ИБ на «сейчас + 10 минут». Тонкий клиент под обычным пользователем и оператором: предупреждение до начала, завершение работы при наступлении.
2. Сеанс с `/UC<код>` и сеанс с `/CЗавершитьРаботуПользователей` не завершаются.
3. Блокировка из формы БСП «Блокировка работы пользователей»: то же поведение, плюс принудительное завершение оставшихся сеансов через администрирование кластера (параметры текущей ИБ хранятся в `ПараметрыАдминистрированияИБ`, это ее штатное назначение).
4. Фоновые задания и веб-сервисы клиентская логика не закрывает, это ожидаемо.
5. Собственный функционал не сломан: `НастройкиБлокировки` / `УстановитьНастройкиБлокировки` чужих ИБ через RAS, завершение сеансов операторами.
