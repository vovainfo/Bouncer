# Обработка «Назначение информационных баз операторам»

## Контекст

Ограниченный оператор техподдержки работает только с базами из `InformationRegister.РазрешенныеИнформационныеБазы` (`Пользователь` + `ИнформационнаяБаза`). Сейчас базы назначаются построчно через форму списка/записи регистра: неудобно и легко ошибиться. Нужна обработка: слева ограниченные операторы, справа дерево кластеров и баз с флажками. Отмеченные базы и есть разрешенные для выбранного оператора.

Правки по ревью: [`ревью-назначение-баз-ограниченным-операторам.md`](ревью-назначение-баз-ограниченным-операторам.md). Приняты пункты 1–5 и часть пункта 6 (`useStandardCommands`/`defaultForm`). Не приняты:
- `validate_form_model` в EDT-MCP есть, проверка остается;
- `НЕ ЭтоГруппа` в запрос не добавлять: `Справочник.Пользователи` не иерархический, поля `ЭтоГруппа` у него нет, группы пользователей лежат в отдельном справочнике `ГруппыПользователей`.

При реализации отказались от признака `ПропуститьАктивизацию`. После «Отмены» строка возвращается на `ТекущийОператор`, а повторную активизацию уже отсекает проверка «оператор в строке совпадает с `ТекущийОператор`». Признак был бы рискованным: если платформа не вызовет активизацию при программной смене строки, он «съел» бы следующее настоящее переключение.

## Решение

### 1. `CommonModule.ПраваУправленияСеансами` (DRY: правило «ограниченный оператор» остается в одном месте)

- Служебные `ЭтоПолноправныйПользователь()` и `РолиДоступны(ИменаРолей)` получают необязательный параметр `Пользователь = Неопределено` и передают его в `Пользователи.ЭтоПолноправныйПользователь(Пользователь, , Ложь)` / `Пользователи.РолиДоступны(ИменаРолей, Пользователь, Ложь)`. Если передано Неопределено, БСП берет текущего пользователя, так что прежние вызовы работают как раньше.
- `МожноЗавершатьСеансы(Пользователь = Неопределено)` и `ИнформационныеБазыДоступныБезОграничения(Пользователь = Неопределено)` получают такой же необязательный параметр. Существующие вызовы не меняются.
- Новая `ЭтоОграниченныйОператор(Пользователь = Неопределено) Экспорт` = `МожноЗавершатьСеансы(П) И Не ИнформационныеБазыДоступныБезОграничения(П)`. `ОграничиватьТипЗавершаемогоКлиента()` начинает вызывать ее, чтобы правило не дублировалось. Пользователь с обеими ролями операторов в список не попадает: ему базы доступны без ограничения.
- Новая `МожноНазначатьИнформационныеБазы() Экспорт` = `ЭтоПолноправныйПользователь()`.
- Новая служебная `ПроверитьПравоНазначенияИнформационныхБаз()`: если `МожноНазначатьИнформационныеБазы()` вернула Ложь, то `ПротоколУправленияСеансами.ЗаписатьОтказВДоступе(Неопределено, Описание)` и `ВызватьИсключение` (так же, как в `ПроверитьПравоУправленияБлокировкой`).
- Новая `ОграниченныеОператоры() Экспорт`: массив `СправочникСсылка.Пользователи`.
  - Начинается с `ПроверитьПравоНазначенияИнформационныхБаз()`. У операторов нет права чтения справочника `Пользователи`, без этой проверки запрос упал бы ошибкой доступа.
  - Запрос по `Справочник.Пользователи` с условиями `НЕ ПометкаУдаления`, `НЕ Недействителен`, `НЕ Служебный`, `ИдентификаторПользователяИБ <> &ПустойУникальныйИдентификатор`, `УПОРЯДОЧИТЬ ПО Наименование`.
  - Затем отбор по `ЭтоОграниченныйОператор(Пользователь)`. Права берутся из фактических ролей пользователя ИБ, а роли одним запросом к справочнику не прочитать.
- `РазрешенныеИнформационныеБазы(Пользователь = Неопределено)`:
  - без параметра или с текущим пользователем поведение прежнее (так вызывает `СеансыИнформационныхБаз`);
  - если передан заполненный пользователь, отличный от `Пользователи.ТекущийПользователь()`, то сначала `ПроверитьПравоНазначенияИнформационныхБаз()`. Функция привилегированная, без этой проверки любой серверный код получил бы список баз чужого оператора.
- Новая `ЗаписатьРазрешенныеИнформационныеБазы(Пользователь, ИнформационныеБазы) Экспорт`:
  - `ПроверитьПравоНазначенияИнформационныхБаз()`;
  - пустой `Пользователь` → `ВызватьИсключение`;
  - в набор попадают только значения типа `СправочникСсылка.ИнформационныеБазыКластера`, остальные отбрасываются;
  - `РегистрыСведений.РазрешенныеИнформационныеБазы.СоздатьНаборЗаписей()`, `Отбор.Пользователь.Установить(Пользователь)`, добавить записи, `Записать()`.
  - Протокол пишет уже существующий `RecordSetModule.ПриЗаписи`: одна запись на сохранение, с полным составом баз. Второй вызов протокола не нужен.

### 2. `DataProcessor.НазначениеИнформационныхБазОператорам` (новый)

- Синоним «Назначение информационных баз операторам». Создать через `create_metadata` и включить в `Subsystem.УправлениеСеансами`, не в `СтандартныеПодсистемы`.
- Как у `DataProcessor.УправлениеСеансами`: `useStandardCommands = true`, `defaultForm = DataProcessor.НазначениеИнформационныхБазОператорам.Form.Форма`. Без них команды открытия в подсистеме не будет.
- Роли не трогаем: у `ПолныеПрава` стоит `setForNewObjects`, операторам обработка недоступна.

**Форма `Форма`** (основная), реквизиты:
- `Операторы`: ТаблицаЗначений {`Пользователь`: СправочникСсылка.Пользователи};
- `ДеревоБаз`: ДеревоЗначений {`Объект`: СправочникСсылка.КластерыСерверов, СправочникСсылка.ИнформационныеБазыКластера; `Представление`: Строка; `Пометка`: Число(1,0)};
- `ТекущийОператор`: СправочникСсылка.Пользователи — оператор, чьи отметки сейчас в дереве;
- `ОжидаетсяОтветНаВопрос`: Булево — пока ответ не получен, новые активизации строк не обрабатываются;
- `ПропуститьАктивизацию`: Булево — возврат строки после «Отмены» не задает вопрос повторно.

Элементы: горизонтальная группа. Слева таблица `Операторы` (только просмотр). Справа дерево `ДеревоБаз`: колонка `Пометка` (ПолеФлажка, `ТриСостояния = Истина`) и `Представление` (только просмотр). Командная панель: `Записать` (кнопка по умолчанию), `Обновить`, `ОтметитьВсе`, `СнятьВсеОтметки`.

Поведение модуля формы:

- `ПриСозданииНаСервере`: если `ПраваУправленияСеансами.МожноНазначатьИнформационныеБазы()` вернула Ложь, то `Отказ` и сообщение через `ОбщегоНазначения.СообщитьПользователю`. Иначе заполнить `Операторы` из `ОграниченныеОператоры()`, построить дерево и загрузить отметки первого оператора.
- Дерево строится из `СеансыИнформационныхБаз.СостоянияИнформационныхБаз(Ложь)`: только справочники, без RAS, базы с пометкой удаления не входят. Для полноправного возвращаются все базы. Цикл построения такой же, как в `ЗаполнитьДеревоНаСервере` формы `УправлениеСеансами`.
- `ЗагрузитьОтметкиНаСервере(Оператор)`: проставить `Пометка` баз из `РазрешенныеИнформационныеБазы(Оператор)`, пересчитать узлы кластеров, `ТекущийОператор = Оператор`, `Модифицированность = Ложь`. Без сброса закрытие формы и каждая смена строки задавали бы вопрос всегда.

**Смена оператора:**
- `ОператорыПриАктивизацииСтроки`: обработчик ожидания 0,2 с гасит прокрутку, как `ДеревоБазПриАктивизацииСтроки` в существующей форме.
- Отложенный обработчик:
  1. Если `ПропуститьАктивизацию`, сбросить признак и выйти. Если `ОжидаетсяОтветНаВопрос`, выйти.
  2. Если оператор в строке совпадает с `ТекущийОператор`, выйти.
  3. Если `Модифицированность = Ложь`, вызвать `ЗагрузитьОтметкиНаСервере(НовыйОператор)`.
  4. Иначе `ОжидаетсяОтветНаВопрос = Истина` и `ПоказатьВопрос` через `ОписаниеОповещения` (Да / Нет / Отмена), в `ДополнительныеПараметры` передать нового оператора. До ответа `ТекущийОператор` не меняется и отметки не перечитываются.
- `СменаОператораЗавершение(Ответ, НовыйОператор)`: сначала `ОжидаетсяОтветНаВопрос = Ложь`.
  - Да: `ЗаписатьОтметки()` для `ТекущийОператор`, затем `ЗагрузитьОтметкиНаСервере(НовыйОператор)`.
  - Нет: `ЗагрузитьОтметкиНаСервере(НовыйОператор)`.
  - Отмена: `ПропуститьАктивизацию = Истина`, текущую строку `Операторы` вернуть на строку `ТекущийОператор`.

**Флажки дерева (`ДеревоБазПометкаПриИзменении`):**
- Платформа уже переключила значение по кругу 0 → 1 → 2. Если получилось 2, ставим 0 (тот же прием в [`ВыборОбъектовМетаданных`](src/CommonForms/ВыборОбъектовМетаданных/Module.bsl), `СледующееЗначениеПометкиЭлемента`). Правило одинаковое для кластера и базы, у базы квадрат не остается.
- Кластер: его значение (0 или 1) ставится всем подчиненным базам.
- База: родитель пересчитывается так: все подчиненные 1 → 1; все подчиненные 0 → 0; иначе 2. У кластера без баз всегда 0.
- После любого изменения `Модифицированность = Истина`.
- `ОтметитьВсе` / `СнятьВсеОтметки`: всем узлам 1 / 0, `Модифицированность = Истина`.

**Запись и закрытие:**
- `ЗаписатьОтметки()` (клиент): собрать `Объект` только из строк баз, то есть подчиненных строк дерева с `Пометка = 1`; узлы кластеров не брать. Затем `ЗаписатьОтметкиНаСервере(ТекущийОператор, Базы)` (`&НаСервереБезКонтекста`) → `ПраваУправленияСеансами.ЗаписатьРазрешенныеИнформационныеБазы`, после него `Модифицированность = Ложь`. Метод общий для команды `Записать`, ответа «Да» при смене оператора и закрытия формы.
- `ПередЗакрытием`: `ОбщегоНазначенияКлиент.ПоказатьПодтверждениеЗакрытияФормы(Новый ОписаниеОповещения("ЗаписатьИЗакрыть", ЭтотОбъект), Отказ, ЗавершениеРаботы)`.
- `ЗаписатьИЗакрыть(Результат, ДополнительныеПараметры) Экспорт`: `ЗаписатьОтметки()`, затем `Закрыть()`.
- `Обновить`: если есть несохраненные изменения, сначала тот же вопрос Да / Нет / Отмена. Затем перечитать операторов и дерево, сохранить текущего оператора, если он остался в списке, иначе взять первого.

Записи регистра по базам с пометкой удаления при сохранении пропадают, так как их нет в дереве. В доступе такие базы и так не учитываются (`РазрешенныеИнформационныеБазы` их отсекает). Если пометку потом снимут, базу придется назначить заново.

## Проверка

1. Запрос операторов проверить через `validate_query`. После записи кода запустить `get_project_errors` / `get_problem_summary` по объекту, `validate_form_model` для формы и `get_form_layout_snapshot` (`compact`).
2. `update_database` (не full), затем запуск под администратором: в левом списке только пользователи, у которых в ИБ есть роль `ОграниченныйОператорТехподдержки`, без операторов и полноправных. Пользователь, только что включенный в группу доступа, появится после обновления ролей его пользователя ИБ.
3. Отметить базы, записать. В форме списка регистра появились строки, в протоколе одна запись «Изменение настроек администрирования».
4. Флажки:
   - щелчок по снятому флажку кластера отмечает все его базы, щелчок по отмеченному снимает их все;
   - частичный выбор дает кластеру третье состояние;
   - щелчок по флажку базы не оставляет квадрат;
   - в регистр не попадают ссылки кластеров.
5. Смена оператора с несохраненными изменениями:
   - «Да» записывает отметки прежнему оператору;
   - «Нет» отбрасывает их;
   - «Отмена» возвращает строку, не задает вопрос повторно и не затирает отметки.
   Закрытие формы с изменениями предлагает записать. Без изменений ни смена оператора, ни закрытие вопроса не задают.
6. Под ограниченным оператором: обработки нет в интерфейсе, а в «Управлении сеансами» видны ровно назначенные базы. Вызов `РазрешенныеИнформационныеБазы(ДругойПользователь)` дает отказ и запись в протоколе.
7. Под полноправным команда открытия обработки видна в подсистеме «Управление сеансами».
8. Под оператором (не ограниченным) по-прежнему ограничение типа клиента не действует (регрессия `ОграничиватьТипЗавершаемогоКлиента`).
