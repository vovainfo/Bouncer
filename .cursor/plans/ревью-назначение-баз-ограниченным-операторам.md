# Ревью плана назначения баз

Сверка с [`ПраваУправленияСеансами`](src/CommonModules/ПраваУправленияСеансами/Module.bsl), [`СеансыИнформационныхБаз`](src/CommonModules/СеансыИнформационныхБаз/Module.bsl), регистром [`РазрешенныеИнформационныеБазы`](src/InformationRegisters/РазрешенныеИнформационныеБазы/РазрешенныеИнформационныеБазы.mdo), формой [`УправлениеСеансами`](src/DataProcessors/УправлениеСеансами/Forms/Форма/Module.bsl) и БСП `Пользователи` / `ВыборОбъектовМетаданных`. EDT-MCP в этой сессии не подключен, вывод по исходникам.

Подход верный: обработка только для полноправного, правило ограниченного оператора остается в одном месте, дерево строится без RAS, запись идет набором с отбором по пользователю, протокол уже пишет `ПриЗаписи`. До кода исправить флажки, переключение строки и контракт чтения чужого списка.

## Согласен

- `ЭтоОграниченныйОператор` совпадает с текущим телом `ОграничиватьТипЗавершаемогоКлиента`: `МожноЗавершатьСеансы` и не `ИнформационныеБазыДоступныБезОграничения`. Вызов оттуда убирает дубль, проверка из пункта 7 плана нужна.
- Имя роли `ОграниченныйОператорТехподдержки` само по себе список не строит. `Пользователи.РолиДоступны` для полноправного возвращает Истина на любое имя роли, до разбора списка (модуль `Пользователи`, после проверки `РольПолныеПрава`). Формула плана как раз отсекает полноправного и обычного оператора. Пользователь с обеими ролями в список не входит: базы ему доступны без ограничения. Так и должно быть.
- Необязательный `Пользователь = Неопределено` у служебных `ЭтоПолноправныйПользователь` и `РолиДоступны` совместим с текущими вызовами. БСП считает Неопределено текущим пользователем. Третий аргумент `Ложь` сохраняет контракт «без учета привилегированного режима».
- `СостоянияИнформационныхБаз(Ложь)` для полноправного возвращает все непомеченные базы. Цикл `ЗаполнитьДеревоНаСервере` для нового дерева подходит.
- Набор с `Отбор.Пользователь` и `Записать()` заменяет срез одного оператора. [`RecordSetModule.ПриЗаписи`](src/InformationRegisters/РазрешенныеИнформационныеБазы/RecordSetModule.bsl) пишет одну операцию `ИзменениеНастроекАдминистрирования` со всем составом. Второй вызов протокола из новой функции не нужен. Внутри транзакции записи набора ошибка протокола откатывает назначение. Это текущее правило проекта.
- Строки по базам с пометкой удаления при записи пропадают, потому что их нет в дереве. `РазрешенныеИнформационныеБазы` такие базы и так отбрасывает. Потеря назначения после снятия пометки приемлема, план это уже фиксирует.
- Роли не трогать. У `ПолныеПрава` стоит `setForNewObjects`, у обеих ролей оператора флаг выключен, регистра в их правах нет.
- Обход пользователей с `РолиДоступны` на каждого уместен. Роли лежат у пользователя ИБ, одним запросом к справочнику их не прочитать.

## Исправить до реализации

### 1. Щелчок по флажку кластера не снимает отметку

План превращает на кластере значение 2 в 1. Платформа к `ПриИзменении` уже сменила флажок по циклу 0, 1, 2. Установленный флажок следующим щелчком становится 2, и обратное превращение в 1 оставляет кластер отмеченным.

В [`ВыборОбъектовМетаданных`](src/CommonForms/ВыборОбъектовМетаданных/Module.bsl) это уже зафиксировано: если платформа поставила 2, вернуть 0. То же правило нужно и кластеру, и базе. Квадрат на базе нельзя оставлять: в набор план кладет только `Пометка = 1`, такая база молча не запишется.

Пересчет родителя в плане двусмысленный: «все отмечены 1, ни одной 0, иначе 2». При буквальном чтении родитель не становится 0. Правило такое: все подчиненные 1, тогда 1; все подчиненные 0, тогда 0; иначе 2.

### 2. Смена оператора затрет несохраненные отметки

`ПриАктивизацииСтроки` приходит, когда строка уже другая. `ПоказатьВопрос` в управляемой форме асинхронный, в форме сеансов для этого уже есть `ОписаниеОповещения`. Пока ответа нет, `ТекущийОператор` не менять и отметки не перечитывать. Иначе «Да» запишет набор новому оператору или запишет пустой набор.

«Отмена» возвращает строку и снова вызывает активизацию. Нужен признак пропуска, иначе вопрос повторится.

Задержку 0,2 с оставить: она гасит прокрутку, как в дереве сеансов. Отложенный обработчик только решает, спрашивать или загружать. Загрузка идет после ответа. После программной установки отметок сбросить `Модифицированность`, иначе закрытие и следующая смена строки спрашивают всегда.

### 3. В набор нельзя класть ссылку кластера

`Объект` в дереве составного типа. У полностью отмеченного кластера `Пометка = 1` стоит и на узле кластера. Измерение регистра имеет тип `СправочникСсылка.ИнформационныеБазыКластера`. В массив писать только строки баз. Пустую ссылку пользователя отсечь до записи набора.

### 4. Чтение чужих баз расширяет привилегированный контракт

`РазрешенныеИнформационныеБазы` экспортная, читает регистр в привилегированном режиме и сейчас всегда берет `Пользователи.ТекущийПользователь()`. Параметр без проверки даст любому серверному вызывающему список другого оператора. Отказ на форме это не закрывает.

Если пользователь передан, заполнен и это не текущий, при отказе `МожноНазначатьИнформационныеБазы()` писать `ЗаписатьОтказВДоступе` и вызывать исключение, как в `ПроверитьПравоУправленияБлокировкой`. Вызов без параметра оставить прежним: `СеансыИнформационныхБаз` его не передает.

`ОграниченныеОператоры` начать с той же проверки. У оператора нет права чтения справочника `Пользователи`, без отказа запрос упадет ошибкой доступа.

### 5. Закрытие формы

`ОбщегоНазначенияКлиент.ПоказатьПодтверждениеЗакрытияФормы` ждет `ОписаниеОповещения`. Метод этого оповещения записывает набор, снимает `Модифицированность` и закрывает форму. Это тот же метод, что у кнопки `Записать`. В плане его нужно назвать.

### 6. Команда в интерфейсе и проверка формы

У [`DataProcessor.УправлениеСеансами`](src/DataProcessors/УправлениеСеансами/УправлениеСеансами.mdo) включены `useStandardCommands` и `defaultForm`. Новой обработке нужны те же свойства, иначе команды в подсистеме не будет. [`CommandInterface.cmi`](src/Subsystems/УправлениеСеансами/CommandInterface.cmi) сейчас пустой и не в git. После включения в состав проверить, что команда открытия видна полноправному.

Инструмента `validate_form_model` в EDT-MCP нет. После формы смотреть `get_project_errors` по объекту и `get_form_layout_snapshot` в режиме `compact`. Запрос операторов по-прежнему прогнать через `validate_query`.

В запрос операторов добавить `НЕ ЭтоГруппа`: справочник `Пользователи` двухуровневый. Пустой идентификатор пользователя ИБ группу и так отсечет, условие делает отбор явным.

## Проверка

Пункты 3, 6 и 7 плана оставить. Пункт 4 дополнить: щелчок по установленному флажку кластера снимает все его базы, щелчок по флажку базы не оставляет квадрат. Пункт 5: «Отмена» не задает вопрос повторно и не затирает отметки. Пункт 2 формулировать как «роль ИБ», а не «профиль»: пользователь, только что включенный в группу, появится после обновления ролей пользователя ИБ.
