# AGENTS.md — Вышибала

Инструкции для AI-агента в этом репозитории. Общайся с пользователем **на русском**. Код, имена метаданных и комментарии в BSL — на русском, без `ё` и длинного тире.

## Что это

Конфигурация **1С:Предприятие** «Вышибала» (workspace / репозиторий `Bouncer`) — инструмент администратора кластера: хранение настроек RAS и управление сеансами чужих информационных баз.

| Свойство | Значение |
|---|---|
| Проект EDT | `Вышибала` |
| Версия конфигурации | `1.0.1.3` |
| Поставщик | Гуменников Владимир |
| Совместимость | 8.3.27 |
| Режим | управляемое приложение, управляемые блокировки |
| Язык скрипта / язык конфигурации | русский / `ru` (других языков нет) |
| БСП | да, `3.1.12.323` (см. `ОбновлениеИнформационнойБазыБСП`) |

Это **не** типовая учётная конфигурация. Документы, регистры накопления и прикладные справочники номенклатуры здесь не предмет разработки. Собственная логика живёт в подсистеме `УправлениеСеансами`; остальное — урезанная БСП.

## Предметная область

Подсистема командного интерфейса `Subsystem.УправлениеСеансами`. Собственные объекты **не** включать в `СтандартныеПодсистемы`.

```
УчетныеЗаписиАдминистрирования
        ↑
КластерыСерверов ──владелец──▶ ИнформационныеБазыКластера
        │                              │
        └── АдминистраторКластера      └── АдминистраторИнформационнойБазы
```

| Объект | Роль |
|---|---|
| `Catalog.УчетныеЗаписиАдминистрирования` | имя администратора; **пароль не реквизит** |
| `Catalog.КластерыСерверов` | адрес/порт RAS (`1545`), порт кластера (`1541`), учётка кластера |
| `Catalog.ИнформационныеБазыКластера` | подчинён кластеру; `ИмяВКластере` + учётка ИБ |
| `CommonModule.НастройкиАдминистрированияКластеров` | мост к БСП `АдминистрированиеКластера` |
| `CommonModule.СеансыИнформационныхБаз` | список состояний ИБ, сеансы, завершение |
| `DataProcessor.УправлениеСеансами` | UI управления сеансами |

Пароли: `ОбщегоНазначения.ЗаписатьДанныеВБезопасноеХранилище` / `ПрочитатьДанныеИзБезопасногоХранилища` / `УдалитьДанныеИзБезопасногоХранилища` (ключ `"Пароль"`). Регистр `БезопасноеХранилищеДанных` пользователям интерактивно не открывать.

Подключение только **RAS** через платформенный `АдминистрированиеСервера`, не `rac.exe` и не COM. Константа БСП `ПараметрыАдминистрированияИБ` — настройки **текущей** базы, не каталог чужих ИБ; её не использовать как хранилище.

Кластер идентифицируется тройкой адрес RAS + порт RAS + порт кластера. UUID кластера не хранить. Пустая ссылка на учётку = пустые имя и пароль (список администраторов не задан).

Проектный план модели: [`.cursor/plans/хранение-настроек-ras.md`](.cursor/plans/хранение-настроек-ras.md).

### API моста

`НастройкиАдминистрированияКластеров` — серверный, **не** привилегированный целиком:

- `ПараметрыАдминистрированияКластера(Кластер)` — `ТипПодключения = "RAS"`
- `ПараметрыАдминистрированияИнформационнойБазы(ИнформационнаяБаза)`
- `ОписанияИнформационныхБазКластера(Кластер)`
- `ПроверитьПодключение` / `ПроверитьПодключениеКластера`

`СеансыИнформационныхБаз`:

- `СостоянияИнформационныхБаз()`
- `Сеансы(ИнформационнаяБаза)`
- `ЗавершитьСеансы(...)`

Чтение пароля — локально `УстановитьПривилегированныйРежим`, сразу сброс. Реквизиты ссылок — `ОбщегоНазначения.ЗначенияРеквизитовОбъекта`, не через точку.

## Инструменты

Работай с конфигурацией через **EDT-MCP**. Схема MCP и `get_tool_guide` — источник правды по параметрам. Не выдумывай поведение инструментов.

Дополнительно:

- **v8std** — стандарты BSL/SDBL, диагностики АПК/BSLLS/EDT. Сначала `v8std_search` / `v8std_explain_snippet`, полный текст — `v8std_get_page`.
- Файловые инструменты Cursor — только для не-1С файлов (этот `AGENTS.md`, markdown, планы, JSON).

`get_tool_guide` вызывай только для незнакомого, разрушительного или каскадного вызова.

### NEVER

- Не читать и не править `.bsl` файловыми инструментами (`Read` / `StrReplace` / `Write` / `Grep`). Только `read_method_source`, `read_module_source`, `write_module_source`, `search_in_code`.
- Не вызывать `write_module_source` с `mode: replace` для одного метода — это перезапишет **весь** модуль.
- Не ставить плейсхолдер-UUID (`00000000-...`) в `.mdo`. Только криптографически случайные UUID v4. Метаданные создавать через `create_metadata` / `modify_metadata`.
- Не хранить пароль в реквизите, константе, макете или коде. Не читать пароль на клиент при открытии формы — только признак «пароль задан».
- Не делать общий модуль с паролями привилегированным целиком.
- Не менять модули БСП без нужды. Если пришлось — маркеры `// <<МОДИФИКАЦИЯ` … `// >>`, оригинал закомментировать внутри блока.
- Не включать собственные объекты в `СтандартныеПодсистемы`.
- Не использовать константу `ПараметрыАдминистрированияИБ` как каталог чужих баз.
- Не делать `git reset --hard` / `push --force` / `checkout .` без явной просьбы.
- Не коммитить секреты. Не запускать `update_database` с `fullUpdate: true` без явной просьбы.

### ALWAYS

- Перед правкой BSL — `read_method_source`, не весь модуль.
- Перед новым кодом — `search_in_code` и существующие паттерны; для БСП читай `rules/ru/bsl-ssl.md`.
- `rename_metadata_object` / `delete_metadata` сначала без `confirm` (preview), потом с `confirm: true`.
- После записи кода — `get_project_errors` или `get_problem_summary`.
- Новый запрос — `validate_query` до вставки в модуль.
- Сомнения по платформе — `get_platform_documentation`.
- Метаданные ищи по программному `Name`, не по синониму. Двуязычен только тип FQN (`Catalog` / `Справочник`).
- Сообщения пользователю — `ОбщегоНазначения.СообщитьПользователю`, не `Сообщить()`.
- Синонимы и `НСтр` — только язык `ru`.
- Писать код по SOLID, DRY и KISS (см. ниже).

## SOLID, DRY, KISS

- **Single Responsibility** — один модуль/процедура/функция решает одну задачу.
- **Open/Closed** — расширять поведение без ломки существующего кода (новые ветки, адаптеры, параметры), а не правкой всех вызовов.
- **Liskov Substitution** — подмена реализации (демо/live, источник данных) не ломает контракт вызывающего.
- **Interface Segregation** — не тащить лишние параметры и поля «на всякий случай»; контракт ровно под задачу.
- **Dependency Inversion** — зависеть от абстракции (параметры администрирования, мост `НастройкиАдминистрированияКластеров`), а не от конкретной реализации RAS/COM или внутренностей БСП.
- **DRY** — не копировать логику; общее вынести в одну процедуру. Дубли констант, маппингов и разбора структур — ошибка.
- **KISS** — самое простое решение, которое работает; без лишних слоёв, флагов и обобщений «на будущее».

## Стиль BSL (сжато)

Полный текст: [`rules/ru/bsl-coding-style.md`](rules/ru/bsl-coding-style.md).

- Самодокументирующиеся имена, без венгерской нотации и аббревиатур.
- Запросы: параметры, алиасы `КАК`, без запросов в цикле.
- Транзакция: `НачатьТранзакцию` сразу перед `Попытка`; в `Исключение` сначала `ОтменитьТранзакцию`, журнал, `ВызватьИсключение`.
- Булево не сравнивать с `Истина`/`Ложь`.
- Deprecated без префикса (`ПодробноеПредставлениеОшибки()`) не использовать — `ОбработкаОшибок.*`.
- Отдельные роли и профили `УправлениеДоступом` для своей подсистемы не плодить без запроса: у `ПолныеПрава` уже `setForNewObjects`.
