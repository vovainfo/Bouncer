# Вышибала

![Вышибала](doc/vyshibala-splash-600x255.png)

Конфигурация 1С:Предприятия для администратора кластера серверов 1С/программистов/техподдержки. Хранит настройки подключения к RAS и позволяет из одного места смотреть и завершать сеансы в чужих информационных базах, а также управлять блокировкой сеансов и регламентных заданий.

Можно выдать операторам техподдержки право «выкидывать» пользователей из баз, не раздавая им пароли администраторов кластера и баз.

## Возможности

- **Каталог кластеров и баз.** Кластеры серверов (адрес и порт RAS, порт кластера) и подчиненные им информационные базы с именами в кластере. Проверка подключения прямо из карточки.
- **Учетные записи администраторов.** Имена хранятся в справочнике, пароли только в безопасном хранилище БСП. На клиент пароль не передается, форма показывает лишь признак «пароль задан».
- **Управление сеансами.** Дерево «кластер → база» с состоянием блокировок, список сеансов выбранной базы, завершение отмеченных сеансов по одному или пакетом.
- **Блокировка базы.** Блокировка начала сеансов и регламентных заданий, период блокировки, сообщение пользователям, код разрешения.
- **Разграничение прав.** Две роли операторов техподдержки с поставляемыми профилями групп доступа (см. ниже).
- **Протокол.** Все операции и отказы в доступе пишутся в журнал регистрации и в регистр протокола. Старые записи удаляет ночное регламентное задание по заданному сроку хранения.



## Права


| Кто                                | Что может                                                                                    |
| ---------------------------------- | -------------------------------------------------------------------------------------------- |
| Полноправный пользователь          | Всё: справочники, учетные записи, блокировки, пакетное завершение, назначение баз операторам |
| Оператор техподдержки              | Видит все базы, завершает сеансы по одному. Блокировки и пакетное завершение недоступны      |
| Ограниченный оператор техподдержки | Видит только назначенные ему базы и завершает в них только сеансы тонкого и толстого клиента |


Операторы видят справочники кластеров и баз только на чтение. Справочник учетных записей и поля администраторов в карточках им не показываются.

Базы ограниченным операторам назначает полноправный пользователь в обработке **«Назначение информационных баз операторам»**: слева операторы, справа дерево кластеров и баз с флажками.

## Как это работает

Подключение идет только через **RAS** (сервер администрирования кластера), платформенным объектом `АдминистрированиеСервера` через подсистему БСП «Администрирование кластера». COM-соединения не используются.

Кластер определяется тройкой «адрес RAS + порт RAS + порт кластера». UUID кластера не хранится. Если учетная запись администратора не указана, подключение идет с пустыми именем и паролем (подходит, когда список администраторов кластера или базы не задан).

Сеанс определяется номером, именем пользователя и временем начала. Номера сеансов платформа переиспользует, поэтому завершение по одному сеансу сверяет все три поля, чтобы не закрыть чужой сеанс, получивший тот же номер. Пакетное завершение отбирает сеансы по каждому полю отдельно, без сверки точной тройки. Поэтому оно доступно только полноправным пользователям.

## Требования

- 1С:Предприятие **8.3.27** или новее (режим совместимости 8.3.27), управляемое приложение.
- Требование версии платформы распространяется только на разворот конфигурации. **RAS**ы, через которые идёт управление сеансами, могут быть любых версий.
- Запущенный **RAS**(ы) на сервере кластера.
- Сетевой доступ от сервера, где работает «Вышибала», до RAS (по умолчанию порт `1545`).
- Учетные записи администратора кластера и администраторов информационных баз, если они заданы в кластере. Администратор базы нужен уже для чтения ее сеансов.



## Установка

1. Скачайте `Bouncer_<версия>.cf` со страницы [Releases](https://github.com/vovainfo/Bouncer/releases).
2. Создайте пустую информационную базу (файловую или клиент-серверную).
3. В Конфигураторе: «Конфигурация → Загрузить конфигурацию из файла», затем «Обновить конфигурацию базы данных».
4. Запустите базу в режиме 1С:Предприятие и дождитесь первоначального заполнения БСП.
5. Создайте пользователей и включите операторов в группы доступа «Оператор техподдержки» или «Ограниченный оператор техподдержки».



## Начало работы

1. **Учетные записи администрирования**: заведите администратора кластера и администраторов баз, задайте пароли.
2. **Кластеры серверов**: адрес и порт RAS, порт кластера, администратор кластера. Нажмите «Проверить подключение».
3. **Информационные базы кластера**: для каждой базы имя в кластере и ее администратор.
4. Если есть ограниченные операторы, назначьте им базы в обработке «Назначение информационных баз операторам».
5. Откройте **«Управление сеансами»**, выберите базу в дереве, отметьте сеансы и завершите их.

Срок хранения протокола задается константой «Срок хранения протокола операций (дней)». Значение `0` означает «не удалять».

## Разработка

Проект ведется в **1C:EDT** (2026.1). Корень репозитория является корнем EDT-проекта «Вышибала».

```
src/          исходники конфигурации (.mdo, .bsl, формы)
doc/          картинки для документации
rules/ru/     правила разработки на BSL
.cursor/      правила и маршрутизация задач для AI-агентов (планы в .cursor/plans/ только локально)
AGENTS.md     инструкции для AI-агентов: модель данных, API, ограничения
```

Чтобы открыть проект: в EDT «Файл → Импорт → Существующие проекты» и указать каталог клона.

Основа — урезанная БСП 3.1.12. Собственная логика лежит в подсистеме командного интерфейса `УправлениеСеансами`: справочники `КластерыСерверов`, `ИнформационныеБазыКластера`, `УчетныеЗаписиАдминистрирования`, общие модули `НастройкиАдминистрированияКластеров`, `СеансыИнформационныхБаз`, `ПраваУправленияСеансами`, `ПротоколУправленияСеансами`. Подробности модели и программного интерфейса описаны в [AGENTS.md](AGENTS.md).

Пароли не попадают в репозиторий: они живут только в безопасном хранилище информационной базы.
